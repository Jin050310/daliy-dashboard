# T05 준비 기록 (AI A 시작 전 고정)

이 문서의 기능·검사·상한은 AI A 시작 전에 고정했다. 이후 변경하지 않는다.

## 개선할 기능
**기간 변동 조회.** 대시보드에서 사용자가 시작일과 종료일을 입력하면, 그 기간의 시작·종료 평가액, 변동률, 최고·최저일, 거래일 수를 보여 준다.

- 계산: `period.mjs`의 `periodSummary(rows, startText, endText)` (형식은 `tests/period.test.mjs` 머리말 참고)
- 화면: `build_dashboard.py`가 만드는 `site/index.html`에서 실시간 데이터(`daily_value.csv` 전체)로 동작
- 휴장일 규칙: 시작일이 휴장이면 그 뒤 첫 거래일, 종료일이 휴장이면 그 앞 마지막 거래일을 쓴다.
- 범위 초과: 종료일이 데이터 마지막 날보다 뒤면 마지막 거래일까지로 자르고 "최신 거래일 YYYY-MM-DD까지"를 안내한다.
- 변동률: (종료 − 시작) ÷ 시작 × 100, 소수 둘째 자리 반올림

### AI A 세부 기록
- 작업 방식: AI가 에이전트 모드로 저장소 파일을 직접 수정하고 검사를 직접 실행했다. 사람은 최초 요청 1회만 보냈다.
- 바뀐 파일: `period.mjs`(새 파일, 계산 함수), `build_dashboard.py`(기간 조회 화면 연결, +54줄)
- 검사 실행: AI 세션 안에서 실행해 10/10 통과로 보고. A 종료 후 확인 실행 10/10 → `T05_records/A_종료_검사결과.txt`
- 계획과 다른 점: 계산 함수까지만 하고 멈출 계획이었으나, 한 번의 요청으로 화면 연결 코드까지 적용됐다.
- 중간 점검에서 발견한 남은 문제: 화면 결과의 날짜 표시가 깨진다. 기존 `fmtDate`는 `YYYYMMDD`를 받는데 기간 결과는 `YYYY-MM-DD`를 넘긴다 (예: `2026.-1.0-`). 고정 검사는 계산 함수만 확인하므로 이 문제를 잡지 못한다.
- 인수인계: 두 번째 요청(15:48)으로 AI가 `HANDOFF.md`를 작성하고, 새 임시 clone에서 실행 명령을 직접 확인했다(코드 수정 없음).
- A 합계: 메시지 2회 / 실제 작업 약 6분(2분 + 4분) / 첫 메시지~인수인계 완료 경과 29분(15:23~15:52, 중간 검토 대기 포함). 어느 기준으로도 상한(60분·30회) 이하.
- 사람 확인: 새 폴더에 저장소를 clone해 `HANDOFF.md` 실행 명령을 그대로 실행 → 설치 성공, 검사 10/10, step7·step8·`build_dashboard.py` 성공 (C11).
- 버전 ID: `HANDOFF.md`의 `22b8191`은 코드 기준 커밋이다. 그 뒤 커밋은 `HANDOFF.md`와 기록 파일만 추가하며 코드는 바뀌지 않는다 (`git diff --stat 22b8191 HEAD`로 확인 가능).

### AI B 세부 기록
- 작업 방식: A와 다른 서비스의 웹 채팅. 로컬 폴더에 직접 접근할 수 없어 저장소 파일 5개(`HANDOFF.md`, `T05_준비.md`, `period.mjs`, `build_dashboard.py`, `tests/period.test.mjs`)를 첨부했다. 이전 대화 내용은 제공하지 않았다 (C13).
- 최초 요청: A와 같은 문장 + "첨부한 HANDOFF.md를 먼저 읽고 이어서 작업. 파일을 직접 고칠 수 없으니 바꿀 코드를 알려 주면 내가 적용"을 덧붙였다.
- 인수인계 누락: 없음. B는 추가 질문 없이 `HANDOFF.md`의 남은 문제(날짜 표시)를 바로 짚고 수정안을 냈다 (C15).
- 바뀐 파일: `build_dashboard.py`의 기간 조회 결과 렌더링. `YYYY-MM-DD`를 `YYYY.MM.DD`로 바꾸는 `fmtPeriodDate`를 추가하고 결과·안내 문구에 적용. `period.mjs`와 검사 파일은 바꾸지 않았다.
- 코드 적용: B가 준 "수정 후" 코드를 사람이 복사해 전달했고, 별도 도구가 내용 수정 없이 그대로 교체했다.
- 검사 실행: 1회차 16:37:42 → 10/10 (`T05_records/B_1회차_검사결과.txt`). FAIL 회차 0.
- 화면 확인(사람): 브라우저에서 2026-10-05 ~ 2026-10-14 조회 → "적용 기간 2026.10.06 ~ 2026.10.14 · 거래일 6일", 변동률 -13.87%. 10-05(개천절 대체공휴일) 휴장 보정과 날짜 표시가 정상.
- 참고: 로컬 미리보기는 `daily_value.csv`가 오래돼 처음엔 11-03까지만 보였다. `step7_daily_value.py`로 다시 만든 뒤 최근일 2026-11-16 확인 (데이터 재생성일 뿐 코드 변경 아님).
- B 합계: 메시지 1회 / 약 6분 (16:34~16:40). 상한(60분·30회) 이하.
